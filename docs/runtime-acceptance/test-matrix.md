# Toli native runtime acceptance matrix

## Execution contract

Run the current workspace source on the iPhone simulator named **Toli UI Acceptance**. The coordinator owns all Xcode builds, simulator operations and UI-test execution; parallel simulator control is prohibited. `ToliUITests` uses XCTest and the ordinary app launch, consent control and real Supabase guest entry. It neither clears Keychain nor deletes an account. The target must not enable parallel UI-test execution.

The selected backend is the dedicated 139 project, `hdapofqufmxlghmcrftg`. Only isolated acceptance accounts may be changed. Product identifiers remain empty, no purchase is initiated, and no production payment result is inferred. Root-page screenshots wait for loaded server-backed catalog/profile controls before capture. Screenshots and failure accessibility hierarchies are retained as XCTest attachments. This document defines the coverage; actual execution results belong in the coordinator's run evidence.

Button helpers choose an already interactive match before attempting scrolling; linked-recipe dismissal explicitly targets the navigation bar Close and waits to return to replay controls before closing the replay itself. This prevents a hidden background replay button from consuming modal actions.

Scroll helpers prefer the visible `page-scroll` or `chat-history` viewport and exclude viewports 150 points or shorter, preventing the keyboard suggestion strip or horizontal category filters from consuming vertical reachability gestures. The helper does not dismiss the keyboard to hide a page reachability failure. It uses at most 24 short drags derived from the current page viewport, at the right gutter to avoid nested text views; each move is capped at 35% of the visible height and shrinks near a target. A fully visible but inaccessible element produces an occlusion hierarchy/screenshot instead of repeated overshooting swipes. Replay progress is read from the production `replay-progress` accessibility element, fed by an AVPlayer periodic time observer. The paused-stability check is an inverted state expectation over three seconds with a 0.3-second observer tolerance; it is not a fixed sleep.

Text replacement uses the actually observed search `Clear text` button or an actually present native Select All editing action after a bounded long-press/double-tap sequence. When the native field exposes no menu, a triple-tap paragraph-selection fallback deletes the selected paragraph; replacement is still forbidden unless the complete old value is verified empty. It verifies the previous value is completely removed and the final value exactly matches the requested text; it never assumes tapping positions the caret at the end. Failed native editing menus retain their actual hierarchy and screenshot.

All waits are bounded state predicates or XCTest existence waits. There are no fixed sleep calls. A media-loading failure fails playback acceptance instead of being silently accepted as a successful player. PDF checks confirm loading finishes without the app's error label and retain a screenshot for visual PDF validation; rendering quality still requires screenshot review.
